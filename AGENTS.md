# Agent instructions

## Required VENIN session debrief

At the start of every session, read `docs/session-debriefs/README.md` and the latest `docs/session-debriefs/YYYY-MM-DD.md`, including all same-day entries, before substantive work. Check for a newer dated file; verify the current branch, commit and working tree.

If no debrief exists, create the directory, index and first dated record from observed state; say that no previous daily record was found. Use Australia/Adelaide dates. Before the final handoff of every coding, planning, design, review or documentation session, finalise a timestamped entry with completed work, actual checks and results, current revision, unfinished work, blockers, authority limits, untouched local changes and ordered next steps. Update the index's latest link.

Append later sessions and corrections; preserve closed entries. Keep secrets, private correspondence, commercial terms and member data out of Git. This is a public repository, so the debrief is redacted: no names, accounts, email addresses, machine paths, client or private-repository names, or details of other sessions; say "the owner" and record engineering state, checks and next steps only. A debrief does not grant implementation, mail, spend, merge or deployment authority.

Read `docs/AGENT_GUIDE.md` before running this tool or writing issues for it.
